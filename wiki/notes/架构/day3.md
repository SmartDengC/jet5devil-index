## 008、布隆过滤器在亿级流量电商系统应用

商城用户 - 商城应用- redis服务器 - 数据库

爬出/流量攻击，查询的数据在数据库中不存在，会直接绕过redis，直接在数据库里面进行查询，叫作**缓存穿透。**

缓存穿透攻击是指恶意用于在短时间内大量查询不存在的数据，导致大量请求被送达数据库进行查询，当请求数量超过数据库负载上限时，使系统相应出现高延迟甚至瘫痪的攻击行为。

**如何预防缓存穿透？**

一个二进制数组，存放到redis服务器。

0 -> 1

如何误判？

- 增加二进制数组位数
- 增加hash次数



```java
       <dependency>
            <groupId>org.redisson</groupId>
            <artifactId>redisson-all</artifactId>
            <version>3.16.1</version>
        </dependency>
```



使用流程

- 应用启动时，初始化布隆过滤器
- 用户发来请求，判断布隆过滤器是否包含编号，
  - 不包含直接返回数据不存在
  - 包含的话，读取redis缓存数据；如果redis缓存数据不存在时，读取数据库，载入redis缓存。

假如商品被删除了该怎么办？

- 布隆过滤器因为某一位二进制可能被多个编号hash应用，因此无法直接处理删除数据的情况。
- 解决：1定时一部重建布隆过滤器（每过4个小时，在另外服务器生成过滤器，然后替换当前布隆过滤器）
- 解决：2计数Bloom Filter（增加一个位数的应用次数）

## 010、5分钟大白话什么是CAP定理

一致性，可用性，分区容错性

一致性：更新操作成功后，所有节点在同一时间的数据完全一致

可用性：代表用户访问数据时，系统是否能在正常相应时间返回预期的结果

分区容错性：代表分布式系统遇到某个节点出错时，仍能够对外提供满足一致性和可用性



cap不能够同时满足，所以就有三个模式

以创建订单和减少库存为例。

cp 表现为订单创建之后需要等到库存减少后才返回，如果某个流程处理慢，就需要一直等待（银行多用）

ap  表现为订单创建后不等待库存减少直接返回处理结果（互联网应用多用）

ac 表现为不再拆分数据系统，在一个数据库的一个事务中完成操作，也就是单体应用



## 011、关于负载均衡器，你学会了吗

**什么是负载均衡器？**

高可用，使每一台设备压力平均分配。

**负载均衡器有哪些？**

硬件负载均衡 

软件负载均衡

- 4层代理（传输层，tcp） ：LVS 虚拟linux服务器
  - 功能性：少，
  - 执行效率：高（更底层，效率更高）
  - 作用协议：tcp
  - 应用场景：实时应用集群，大规模集群见数据交互

- 7层代理（应用层，http）： Nginx
  - 功能性：多，支持资源压缩，更多策略
  - 执行效率：相对较低
  - 作用协议：http，ftp， smtp
  - 应用场景：web应用集群，需要更多额外功能的应用集群。

**负载均衡策略有哪些？**

nginx是一款轻量级的web反响代理服务器，是目前使用最多的软件负载均衡器。

轮询策略（默认）： 排排坐吃果果，你一口我一口

权重策略： 我比你胖，我多吃一口

IP_HASH：一个萝卜（IP）一个坑，对ip取模

URL_HASH：一个白菜一个坑，url的地址取模运算

## 012、阿里开发规范，为啥禁用外键约束

阿里JAVA规范

不得使用外键与级联，一切外键概念必须在应用层解决。

每次做delete或者update都必须考虑外键约束，会导致开发的时候很痛苦，测试数据极为不方便。

保证数据的完整性和一致性，级联操作方便，数据一致性交给数据库，代码量小。



以一个订单表和一个订单明细表，订单明细表里面外键关联订单表的ID

性能问题，额外的数据一致性校验查询

并发问题，外键约束会启用行级锁。当校验订单明细表中的订单id是，会给订单表里面这条数据加一个共享锁（读锁），这个时候如果有排它锁（写操作）的话， 会出现线程积压。

级联删除问题，多层级联删除会让数据不可控，触发器也被禁用

数据耦合，数据库层面数据关系产生耦合（如果其中一个表的数据过大，需要做迁移到其他数据库，这个时候就会删除到主键关联，但是程序中有没有做这些数据的校验，导致数据不一致，需要在程序中校验）

什么是异构数据？

mysql的数据和es的数据结构不同，称为异构数据。

在java代码中新增mysql数据时想调用团队b同步接口新建ES商品数据



团队A与团队B强耦合。

团队A必须了解团队B提够的接口才可能实现，但本身这并不属于团队A的工作范畴。

扩展困难。团队C维护mongoDB也需要同步mysql数据库，难道要团队A又要改代码？等排期把？



要保证数据做到准实时同步，还要团队之间解耦。

canal是阿里旗下的一款开源项目，纯java开发，基于数据库增量日志解析，提供增量数据订阅、消费，目前主要支持了mysql，也支持了mariaDB

主从复制是基于binlog，存储已经执行过的sql语句，从库下如relaylog日志里面，保存了即将执行的主库的sql语句，然后在从库中执行一下。

canal就是一个假的mysql从库，监听relaylog，自动出发java代码实现向ES的同步。

加入一个mq消息队列，canal将执行的信息放到mq里面，然后需要的其他团队 来订阅这个mq。

## 018、Redis架构很难懂吗，Sentinel高可用架构

redis主从复制过程

redis master（写操作）， redis slave（读操作）， redis slave  一主多从架构

建立连接过程

redis 主服务器，会使用bgsave生成rdb快照，然后将rdb快照发送给redis从服务器，从服务器加载rdb还原数据，保持主从一致。

当redis master执行写操作之后，会往slave执行保持数据同步。

redis sentinel 高可用集群（sentinel）

Sentinel节点挂了怎么办？

sentinel自动故障迁移使用raft算法来选举零头 leader，超过半数投票选出leader，sentinel leader用于下达故障转移的指令，如果某个leader挂了，则使用raft从剩余的sentinel种选出leader
